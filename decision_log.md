# Decision Log

## D-001: CRISP-DM is the mandatory methodological framework
**Decision.** Structure all Development-phase work explicitly as CRISP-DM: Business Understanding → Data Understanding → Data Preparation → Modelling → Evaluation → Deployment.
**Alternatives.** None considered — this is a hard requirement, not a choice. `Guidelines/Estructura de documentacion TFM.pdf` and `Guidelines/MIAD TFM_ Exemplos propostas final project.pdf` both mandate it explicitly, and a dedicated explanatory video on CRISP-DM application is a required deliverable.
**Evidence.** Guidelines PDFs, read in full 2026-08-10.
**Consequences.** Notebook and report structure must be organised by CRISP-DM phase, not by ML pipeline stage alone; the video script must map each phase to a concrete artefact in this project.

## D-002: Primary data source is FBref/Opta match-level data via `worldfootballR_data`, not live scraping
**Decision.** Use the pre-scraped, versioned CSV release assets in the public `JaseZiv/worldfootballR_data` GitHub repository (`fb_advanced_match_stats` release) as the primary player-match dataset, rather than scraping FBref directly.
**Alternatives considered.** (a) Direct FBref scraping via `soccerdata.FBref` — rejected: FBref returns HTTP 403 (Cloudflare) from this environment and no Chrome/Chromium is installed to run `soccerdata`'s browser-automation fallback. (b) `soccerdata.Understat` — tested successfully, but schema is attacking-only (19 columns, no passing/defensive/pressing detail) and insufficient alone for a multi-dimensional ontology.
**Evidence.** Both alternatives tested directly (`curl` returned HTTP 403 for FBref; `soccerdata.Understat` returned a working 570-row/19-column sample). See `outputs/audit/data_availability_matrix.md` §4.
**Consequences.** Reproducibility improves (fixed CSV files, not a live/blockable scrape) at the cost of a fixed coverage window (2017/18–2025/26) and no direct control over metric definitions (inherited from FBref/Opta as published).

## D-003: FBref/Opta match-level data and StatsBomb Open Data are never pooled without an explicit harmonisation step
**Decision.** Treat Source A (FBref/Opta match-level) and Source B (StatsBomb Open Data) as two separate, non-interchangeable evidence streams. Guardiola's Barcelona era (only available via Source B) is a separate robustness check, not concatenated into the same feature matrix as his Manchester City era (Source A).
**Alternatives considered.** Pooling both sources into one feature set — rejected outright.
**Evidence.** FBref itself changed data provider from StatsBomb to Opta in late October 2022 (documented in the `worldfootballR_data` repo's own README, `data/fb_big5_advanced_statsbomb/README.md`); direct inspection confirms the match-level release is uniformly Opta-derived (pressing "Pressures" columns present in the legacy StatsBomb-era season file, absent from the match-level file). Two different event-tracking providers do not guarantee identical metric definitions even for identically-named columns.
**Consequences.** No pressing-metric proxy can be directly compared between the Guardiola-Barcelona (StatsBomb) and Guardiola-City (Opta) samples; any Barcelona-era finding is reported as an independent qualitative/robustness signal, not blended into the main quantitative manager profile.

## D-004: Manager attribution must be done at match level using verified tenure dates, never at season level
**Decision.** Every player-match observation is joined to a manager via `first_match_date`/`last_match_date` from the verified tenure table, not via season or club alone.
**Alternatives considered.** Season-level join — rejected as a hard project requirement (brief §12–15), and independently confirmed necessary by the tenure research: 8 of the 20 tenure rows are marked UNSAFE for season-level joins (mid-season appointments/departures), including two of the single most data-rich seasons available (2015/16 Liverpool, 2022/23 Brighton).
**Evidence.** `data/external/manager_tenures.md`/`.csv`, cross-corroborated against 2+ independent sources per row.
**Consequences.** The dataset-construction step (Task #2) must implement match-date-based splitting logic, not a simple season-level merge; StatsBomb's own `managers` field (available for Source B rows) provides an independent cross-check where both sources overlap.

## D-005: Scope excludes Bayern Munich (Guardiola), Dortmund (Klopp), Palermo/Shakhtar (De Zerbi) from quantitative modelling — after an explicit, exhausted search for alternatives
**Decision.** These tenures are documented in the tenure table and ontology for completeness but excluded from the quantitative feature set. **Benevento 2017/18 (De Zerbi) is included as a corrected addition** — full match-level data exists for that season (missed in the first audit pass) — but flagged as low-confidence given the tenure table's own severe-squad-quality warning.
**Alternatives considered and actively tested, not merely deprioritised** (per explicit user request to chase further before accepting this scope, 2026-08-10):
1. FBref's own historical depth — tested empirically via the season-level results file: `Home_xG`/`Away_xG` is 100% null for Bundesliga 2013/14–2015/16 (Bayern/Guardiola era), confirming advanced stats do not exist on FBref itself before ~2017/18, not merely that our mirror lacks them.
2. `worldfootballR_data`'s `match_results` release (scores/dates only, 47 countries, back to 1989) — checked directly, confirmed to lack any passing/tackle/possession detail.
3. Kaggle "European Soccer Database" (Hugo Mathien, 2008–2016 coverage, mirrored on Hugging Face without auth) — schema independently corroborated (Country/League/Match/Player/Player_Attributes/Team/Team_Attributes); "attributes" are FIFA-video-game ratings, not measured performance; match "detailed events" are goal/shot/foul/card/cross/corner/possession box-score data, not passing-network or pressing detail. Download attempted but too slow/unreliable to complete from this environment (~90KB/s on a 313MB file); concluded low-value even if completed, given the schema, and would in any case require a separate non-pooled treatment per D-003.
4. Ukrainian Premier League (Shakhtar 2021/22) and Palermo 2016/17 — no tactically-detailed open dataset located; Ukrainian league absent from StatsBomb's competition list entirely.
**Evidence.** `outputs/audit/data_availability_matrix.md` §1–4 (§4 is the new chase-outcome section).
## D-006: FBref match-level 'passing'/'passing_types'/'possession'/'keeper' blocks do not exist for Serie A/Ligue 1 before 2023/24 -- a critical, previously-undetected data gap, found and fixed during Task #4
**Decision.** Concept computation must never `fillna(0)` a raw or ratio-term column: missing block-level data (entire league/season with no coverage) must propagate as NaN through every stage (terms -> concept scores -> player profiles -> manager profiles -> compatibility), using minutes/weight-aware NaN-skipping aggregation throughout, so "no data" is never silently reported as "exactly league average."
**How this was found.** The club-identity-bias check in `notebooks/04_player_manager_compatibility.ipynb` initially showed Sassuolo and Benevento centroids at cosine similarity ≈ **-0.6 to -0.66** with every other club, while Brighton/Marseille/Liverpool/Man City all clustered at **+0.95 to +0.998** with each other -- a suspiciously clean two-cluster split. Root-causing this (rather than accepting it as a real finding) surfaced a systematic coverage audit result: `passing`, `passing_types`, `possession` and `keeper` are **0% populated for ITA and FRA for Season_End_Year 2018-2023, 100% from 2024 onward**, while `defense` and `misc` are 100% populated everywhere always, and `summary` is 0% populated for **every** league before 2025 (verified by direct per-column, per-league, per-season non-null-rate audit, see `outputs/audit/data_availability_matrix.md` SS5). This had been present since Task #2 but only surfaced once a bias check specifically stressed the affected clubs.
**Consequences.**
1. `chance_creation` and `box_presence` concepts were redefined to drop terms that depend on the unavailable `summary` block entirely (SCA/GCA, shots, npxG) -- `box_presence` in this project now measures box *occupation* only (touches in the box as a share of total touches), not shot quality, for the whole in-scope window, all three managers.
2. Sassuolo (3 full seasons) and Benevento (De Zerbi's two weakest/lowest-confidence tenures anyway, per D-005) have **no usable data at all** for 5 of 7 tactical dimensions (`progressive_passing`, `progressive_carrying`, `possession_retention`, `chance_creation`, `box_presence`) and partial data for a 6th (`individual_defending`, whose ratio term needs the missing `possession` block). Only `pressing_intensity` and (fully) `individual_defending`'s percentage term are unaffected.
3. Every aggregation function in `src/football_features.py` (`build_player_profiles`, `build_manager_profiles`, `build_club_within_manager_profiles`) was rewritten to skip NaN per-column with re-normalised weights, not `fillna(0)` before averaging (see `_nan_aware_wmean`). The population-baseline pooling step (`build_population_baseline`) had the same class of bug (a single zero-coverage league silently poisoning a pooled mean/std to NaN via non-NaN-aware `np.average`) and was fixed the same way.
4. `compute_compatibility` and the club-bias similarity matrix now compute cosine similarity only over the dimensions **both** vectors have a value for (`masked_cosine_similarity`), and record `n_dims_used`/`low_confidence` on every comparison so a thin (1-2 dimension) comparison is visible rather than silently treated as equally reliable as a full 7-dimension one.
**Evidence.** `outputs/audit/data_availability_matrix.md` SS5 (coverage audit); `outputs/results/task4_evaluation_findings.md` (full incident writeup and final, corrected results); `src/football_features.py` and `src/compatibility.py` (fixed code).
**Consequences for the headline result.** Even after every fix above, the best-fit match rate restricted to well-covered (≥4-dimension) comparisons is **32.8%** (n=470), statistically indistinguishable from the ~33% chance baseline for 3 classes -- and the club-bias check still shows De Zerbi's own two well-covered clubs (Brighton, Marseille) resemble each other (0.583) *less* than they each resemble Klopp's/Guardiola's clubs (0.706). This is a genuine, sobering finding, not a residual bug: fixing the data-integrity problems removed a spurious signal but did not reveal a real one underneath it. See `task4_evaluation_findings.md` SS6 for the honest interpretation and recommended paths forward.

**Note added after dataset construction (Task #2, 2026-08-10).** The integrity audit (`outputs/audit/integrity_audit.md`) passed cleanly (zero rows outside their stamped attribution window, zero duplicate player-match rows) and the match counts independently corroborate the tenure table (e.g. Brighton 2022/23 yields exactly 32 De Zerbi matches — Brighton's 38-match season minus the 6 fixtures under Potter/Crofts before his 2022-10-01 debut, matching the tenure table's own accounting). One new, minor finding: Marseille's 2024/25 season shows only 20 of an expected ~34 matches, and 2025/26 only 4 — this is the underlying `worldfootballR_data` release snapshot being incomplete for the most recent seasons (confirmed league-wide, not De Zerbi-specific: Ligue 1 2024/25 shows 306 total matches expected vs. a smaller number present across all teams), not an attribution error. Flagged as a data-completeness limitation for the Marseille sample specifically.

**Consequences.** Guardiola's and Klopp's in-scope quantitative samples remain each single-club (Man City; Liverpool), which weakens the club-identity-bias check (brief §18–19) for those two managers specifically relative to De Zerbi's now-four-tenure sample (Sassuolo, Benevento, Brighton, Marseille). Mitigation unchanged: treat this asymmetry as a stated, honest, *actively investigated* limitation, and use the literature's own independent team-level clustering (Plakias et al. 2025 grouping Barcelona/Bayern/Man City together, and separately Liverpool with Atalanta) as external corroborating evidence not derived from our own model.

## D-007: Analyst-driven feature refinement -- role-based positions, possession-adjusted pressing, goalkeeper distribution
**Decision.** Following a request to review the whole project as a football analyst rather than an engineer, three concrete, football-grounded critiques were identified and implemented rather than left as commentary:
1. **8-way role-based position grouping** replaces the 4 coarse GK/Defender/Midfielder/Forward buckets, using FBref's specific match-level position tags (CB/LB/RB/WB/DM/CM/AM/LM/RM/LW/RW/FW/GK) mapped directly to 8 roles, with a touches-by-third zone heuristic as a fallback for season-level data's coarser DF/MF/FW/GK-only tags (`src/football_features.py::position_group`, `_FINE_GRAINED_MAP`).
2. **Possession-adjusted pressing intensity** (closes long-open OD-5): every pressing_intensity term changed from `rate` to `padj_rate`, multiplying the per-90 rate by `league_avg_opponent_possession / this_team's_opponent_possession` (`attach_possession_adjustment`, sourced from a newly-downloaded team-level FBref possession table, `data/raw/fbref_season/team_possession.parquet`).
3. **New `goalkeeper_distribution` concept** (average pass length, launch %, launch completion %) feeding `TD1_buildup_directness` at weight 0.2 -- using `keeper`/`keepers_adv` block columns that were already being downloaded/merged but never referenced by any concept, despite the project's own qualitative research (`manager_philosophy_hypotheses.md` SS1.2/SS3.2) naming exactly this goalkeeper-as-auxiliary-defender mechanism as a clear discriminator for Guardiola and De Zerbi.

**A necessary fourth change, discovered mid-implementation, not originally planned:** `build_dimension_scores` was rewritten to be NaN-aware per row (renormalising a dimension's weights over only the concepts actually available for that row). Without this, adding `goalkeeper_distribution` (NaN for every outfield player by construction) would have silently NaN'd out `TD1_buildup_directness` for every outfield player, since the un-fixed function summed all weighted concepts unconditionally. Caught before it shipped by inspecting intermediate output, not assumed correct.

**Also discovered mid-implementation:** the first attempt at role-based grouping produced a badly broken distribution (8959 of 10996 rows dumped into one "Central Midfielder" bucket) because match-level FBref data uses a completely different, MORE granular position-tag vocabulary (CB/LB/RB/DM/CM/AM/LM/RM/LW/RW/FW/GK) than season-level data's coarse DF/MF/FW/GK tags -- the original heuristic assumed the coarse vocabulary everywhere. Fixed by mapping the fine-grained tags directly and reserving the zone-heuristic fallback for genuinely coarse-tagged (season-level) rows only.

**Evidence / result.** `outputs/results/task4_evaluation_findings.md` §7a. Best-fit match rate improved from 37.8% (n=558, prior to this round) to **42.1%** (n=561) -- a real, material improvement, not noise. Pressing intensity's permutation importance grew substantially and remains by far the strongest dimension; individual defending turned from net-negative into real signal. The De Zerbi club-bias gap (within-club similarity vs. between-manager similarity) narrowed roughly 6x, from 0.106 to 0.017, though it did not fully close. **(See D-009: the exact permutation-importance figures originally recorded here were wrong and have been corrected.)**
**Consequences.** The project's headline conclusion is revised from "this feature set cannot discriminate the three managers" to "a knowledge-informed feature set, refined with football-analytical judgement, discriminates the three managers meaningfully better than chance, led by pressing intensity, with a residual but much-reduced squad/league-strength confound." All four downstream notebooks (03-06) were re-run in full; `player_profiles.parquet`, `manager_profiles.parquet`, `player_manager_compatibility.parquet`, `player_universe.parquet` and every figure in `outputs/figures/` reflect the new features.

## D-008: Added a formal significance test on the 42.1% best-fit rate, and explored formation as an eighth dimension -- added descriptively instead, after discovering the upstream match-level source had moved past the historical window this project needs

**Decision (significance test).** Added a bootstrap confidence interval and a permutation test around the 42.1% best-fit match rate (`notebooks/04_player_manager_compatibility.ipynb` §2b), since a single point estimate over n=561 does not by itself say how precisely that number is known or how unlikely it would be under a genuine null. Both computed directly from the already-saved `player_manager_compatibility.parquet`, no new data or model changes required.
**Result.** Bootstrap 95% CI (5000 resamples): **[37.8%, 46.2%]**, median 42.1%. Permutation test (5000 shuffles of the true manager label against the model's own decisions): empirical chance baseline **34.0%** (not exactly 33%, because the n=561 sample's manager mix is not perfectly even -- 203/188/170 for De Zerbi/Klopp/Guardiola), **p = 0.0002**. The association between the model's best-fit decision and the true manager is statistically significant at a stringent threshold, but the confidence interval is wide enough (8.5 points end to end) that the exact 42.1% figure should not be read as more precise than it is.
**Evidence.** `outputs/results/task4_evaluation_findings.md` §7b; `outputs/tables/best_fit_significance_test.csv`.

**Decision (formation).** Explored adding the match-level `Home_Formation`/`Away_Formation` columns (collected since task #2, never analysed, and named in the report's own recommended next steps) as an eighth tactical dimension inside the compatibility score.
**What was found while implementing this.** Re-checking source coverage before building the feature showed that `worldfootballR_data`'s `fb_advanced_match_stats` GitHub release is a **rolling asset that its maintainer overwrites in place**, not a versioned per-season snapshot: the files currently downloadable from that release cover the 2025/26 season, and the 2018-2023 window this project needs is no longer available from it at all. The historical formation data was recovered from `data/processed/player_match_manager.parquet`, an intermediate file saved during task #2 that still carries the original snapshot (10996 rows, 0% missing `Home_Formation`/`Away_Formation`). Nothing was lost only because this project's habit of persisting every intermediate stage to `data/processed/` happened to preserve it.
**Why formation was not folded into the compatibility score as an eighth dimension.** Formation is only available for the 22 club-seasons inside the manager-attributed match-level sample, never for the wider 11132-player-season population every other dimension is z-scored against. Standardising a new dimension against a population of 22 would be far more statistically fragile than the other 7 dimensions, so rather than quietly ship a weak eighth dimension, the result is reported as descriptive supporting evidence (`notebooks/04_player_manager_compatibility.ipynb` §7), kept clearly separate from the numerical score.
**Result.** Klopp: modal 4-3-3, 86.5% formation stability (by far the most tactically settled). Guardiola: modal 4-3-3, 59.8% stability, 10 distinct formations used (more experimentation than his "singular possession identity" reputation might suggest). De Zerbi: modal 4-2-3-1, 56.1% stability, 15 distinct formations, lowest mean back-line size (3.81) -- the most structurally fluid of the three by every measure, corroborating his existing qualitative description as an unconventional, fluid tactician on genuinely new, independent evidence.
**Evidence.** `outputs/results/task4_evaluation_findings.md` §7c; `outputs/tables/manager_formation_profile.csv` and `_by_club_season.csv`.
**Consequences.** A pipeline step that only ever re-fetches from a live, unversioned upstream source (rather than caching an original snapshot) is exposed to this exact kind of silent scope loss -- worth remembering for any future extension of this project that needs more historical match-level data than is currently cached in `data/processed/`.

## D-009: Corrected the post-D-007 permutation importance figures, found during a pre-submission fact-check pass -- the reported numbers were wrong

**What happened.** Asked to assess whether the project was ready to submit, a systematic fact-check pass compared every specific numeric claim in `report/memoria.md` and `report/final_report.md` against the actual saved output files, rather than trusting the already-written text. Two errors were found this way, both now corrected:

1. **The "9 club-seasons" formation population size (D-008) was simply wrong.** The manager-attributed sample actually spans **22 club-seasons across 6 clubs** (Liverpool, Manchester City, Sassuolo, Benevento, Brighton & Hove Albion, Marseille), verified directly against `player_profiles.parquet`. Every mention of "9 club-seasons" across `decision_log.md`, `data_dictionary.md`, `outputs/results/task4_evaluation_findings.md`, `app/streamlit_app.py`, `notebooks/04_player_manager_compatibility.ipynb`, `report/memoria.md` and `report/final_report.md` has been corrected to 22. The core argument (too small a population to standardise a new dimension against, next to the 11132-player-season universe the other 7 dimensions use) is unaffected -- 22 is still tiny by comparison -- only the specific number was wrong.
2. **The post-D-007 permutation importance figures were wrong, and materially so.** `decision_log.md` D-007 and every report citing it stated pressing intensity's importance grew to +4.02pp and that box presence and individual defending both flipped to +2.3pp (real signal). An independent, from-scratch recomputation against the actual saved `player_profiles.parquet`/`manager_profiles.parquet` -- run twice, once inside a re-executed `notebooks/04_player_manager_compatibility.ipynb` and once in a standalone script, both exactly reproducing `outputs/tables/dimension_permutation_importance.csv` -- gives the true current values: **pressing intensity +7.49pp** (nearly tripled, not merely doubled, from the pre-improvement +2.55pp), **buildup directness and progression passing +3.21pp each**, **progression carrying +2.67pp**, **individual defending +1.78pp** (real signal, as reported), but **box presence -0.36pp and chance creation -0.71pp** (both still net-negative -- box presence did *not* flip to positive signal as the text claimed).
**Why this is a more interesting result, not a worse one, for the dimensions that actually did move.** Pressing intensity's dominance is stronger than previously described, and three further dimensions (buildup directness, progression passing, progression carrying) turned out to carry genuine positive signal that the earlier, incorrect write-up did not credit at all. The one genuinely disappointing correction is box presence, which the original text incorrectly celebrated as a rescued dimension; the more detailed positional grouping helped individual defending but not box presence.
**How this was caught.** Not by a code bug this time -- the underlying pipeline code and data were never touched during this fact-check pass. The two most likely explanations are a transcription error when the D-007 numbers were first written up, or the numbers being copied from an intermediate run of the notebook that was superseded by a later, final re-run whose output was never re-checked against the text describing it. Either way, this is the same lesson the project has already learned twice (D-006, D-008) in a new form: a number written into a report is a claim that needs to be checked against the actual saved artefact, not assumed correct because it was written down carefully.
**Consequences.** `outputs/results/task4_evaluation_findings.md` §7a, `decision_log.md` D-007 (this entry), `data_dictionary.md`, `report/memoria.md`, `report/final_report.md`, and `app/streamlit_app.py` were all updated to the corrected figures. No pipeline code changed -- this was a documentation-only correction. The headline 42.1% best-fit rate (n=561), the significance test (D-008 addendum, p=0.0002), and the club-bias gap narrowing (0.106 to 0.017) were independently re-verified during this same pass and found to be correct as originally reported.

## D-010: The "Klopp presses harder than Guardiola" claim was wrong -- Guardiola's manager profile actually scores higher on pressing intensity, found during an extensive pre-submission verification pass

**What happened.** Asked to do an extensive verification of the whole project, every qualitative comparative claim involving the three managers' tactical dimension scores was checked directly against `data/processed/manager_profiles.parquet` and the already-embedded `outputs/figures/manager_profiles_bar.png` chart, rather than trusting the already-written narrative. `report/memoria.md` (executive summary, H-P1 status, section 8.3) and `report/final_report.md` (sections on the state of the art, manager profiles, dimension importance, and the closing reflection) all stated or implied that Klopp's manager profile scores higher than Guardiola's on the possession-adjusted pressing intensity dimension, consistent with his *gegenpressing* reputation, and that hypothesis H-P1 was fully "Supported."

**The actual, verified numbers say otherwise.** `TD9_pressing_intensity`: Guardiola **0.304**, Klopp **0.229**, De Zerbi **-0.001** (confirmed directly against the parquet file and visually against the already-published bar chart, which shows Guardiola's orange bar taller than Klopp's blue bar on this dimension). Guardiola's clubs score marginally *higher* than Klopp's, not lower, on the final possession-adjusted measure -- the opposite of H-P1's specific prediction for that pair.

**What still holds.** De Zerbi's score is clearly the lowest of the three, exactly as H-P1 and H-P3 predicted, and pressing intensity remains by a wide margin the single most discriminating dimension in the whole feature set (D-009's corrected permutation importance, +7.49pp). The part of the hypothesis about De Zerbi is confirmed; the part about Klopp specifically outscoring Guardiola is not.

**Most likely explanation, not just an error to shrug off.** The possession adjustment (`attach_possession_adjustment`, closing OD-5 per D-007) corrects a team's raw defensive-action rate for how much possession its *opponents* typically had, not for squad quality in general. Manchester City's possession dominance in this sample is extreme even by elite-club standards, meaning their opponents have unusually little of the ball -- plausibly over-correcting City's adjusted pressing rate upward beyond what pure managerial pressing intent would justify. This is a concrete instance of exactly the residual squad-strength confound this project has documented in general terms since D-006, not a contradiction of the project's own diagnosis.

**Consequences.** `report/memoria.md` (H-P1 downgraded from "Supported" to "Partially supported," section 8.3 rewritten to state and explain the actual result rather than the originally hypothesised one, executive summary softened), `report/final_report.md` (the manager-profiles section, the dimension-importance section, the state-of-the-art hypothesis setup, and the closing reflection all corrected to state Guardiola's marginally higher score honestly, with the possession-adjustment explanation), and `app/streamlit_app.py`'s About section were all updated. The project's central quantitative and significance-test results (42.1% best-fit rate, the D-008 statistical tests, the D-009 permutation-importance corrections) are unaffected -- this correction is specific to the qualitative manager-profile narrative around pressing intensity, not to the compatibility scoring pipeline itself.
